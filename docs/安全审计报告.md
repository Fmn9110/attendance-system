## 一、已发现并修复的严重漏洞

### 1. 路径遍历漏洞（已修复）

**位置**：`backend/app/routers/students.py` — `confirm_import` 接口

**风险等级**：🔴 严重

**漏洞描述**：
导入花名册确认接口直接使用前端传来的 `stored_path` 参数读取文件。攻击者可以构造恶意请求，传入 `../../etc/passwd` 等路径，读取服务器上的任意文件。

**攻击场景**：
```
POST /api/classes/1/students/import/confirm
{"stored_path": "../../../etc/passwd"}
```

**修复方式**：
增加路径校验，确保 `stored_path` 必须在 `upload_dir` 目录内：
```python
upload_dir_abs = os.path.abspath(settings.upload_dir)
path_abs = os.path.abspath(path)
if not path_abs.startswith(upload_dir_abs + os.sep):
    raise HTTPException(status_code=400, detail="非法的文件路径")
```

## 三、已知风险点（低风险，本地系统可接受）

### 1. Token 放在 URL 参数中

**位置**：导出接口为了支持浏览器直接下载，允许通过 `?token=xxx` 传 token。

**风险**：
- Token 会出现在浏览器历史记录中
- Token 会出现在服务器访问日志中
- Token 可能通过 Referer header 泄露

**缓解措施**：
- 系统只在本地运行（127.0.0.1），外部无法访问
- Token 有效期 7 天，过期自动失效
- 如果需要公网部署，应改为 Cookie 认证

### 2. Secret Key 硬编码

**位置**：`config.py` 中 `secret_key: str = "dev-secret-change-me"`

**风险**：如果公网部署且密钥泄露，攻击者可以伪造 token。

**缓解措施**：
- 系统只在本地运行，不暴露到公网
- 如需公网部署，应通过环境变量设置随机密钥

### 3. CORS 配置宽松

**位置**：`main.py` 中 `allow_origins=["*"]`

**风险**：任何网站都可以调用 API，但因为 `allow_credentials=False` 且需要手动传 token，实际风险较低。

### 4. 无登录失败次数限制

**风险**：可以暴力破解班级密码。

**缓解措施**：系统只在本地运行，外部无法访问。
